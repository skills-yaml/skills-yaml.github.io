Use skills in Claude

Install a release-notes skill in Claude chat, Claude Code, or the Messages API. Check that it loads and drafts release notes from your source notes.

Choose your Claude surface

Use the release-notes skill from the first-skill guide in each recipe. Setup checked against Claude’s documentation on November 27, 2026.

  • Claude chat uploads a ZIP through Customize.
  • Claude Code reads the skill folder from disk.
  • Messages API uses a skill ID from your API workspace.

Upload the skill to Claude

  1. Zip the skill folder

    Run zip -r release-notes.zip release-notes/ from the directory containing the skill folder. The ZIP should contain the enclosing folder, with SKILL.md directly inside it. Claude’s ZIP requirements

    release-notes.zip
    release-notes/
└── SKILL.md

  2. Enable code execution and upload

    In Settings → Capabilities, enable Code execution and file creation. The updated layout calls it Create and edit files.

    In Customize → Skills, select +, then Create skill, then Upload a skill. Choose release-notes.zip and turn on its toggle. If your organization already provides the skill, enable that copy.

    If Skills is missing or grayed out, check code execution. On managed accounts, owners can check Organization settings → Plugins & skills → Policy. If you can see skills but cannot upload, check User-created skills and your role. Claude setup and troubleshooting

Draft release notes in a new chat

Send this prompt in a fresh chat.

Claude chat
Use the release-notes skill to draft release notes from these change notes.

- Confirmed: The activity log now offers CSV export.
- Confirmed: Fixed duplicate entries in the activity log after a refresh.
- Unverified: CSV export may be twice as fast as the previous internal prototype.

Check the turn’s activity details if available. Look for a skill-use entry naming release-notes or a read of its SKILL.md. If neither appears, record activation as unknown and check the draft.

To test automatic selection, start a fresh chat and replace the first line with Draft release notes from these change notes. To establish a baseline, repeat that request in a fresh chat with the skill toggled off.

Install the folder in Claude Code

Copy release-notes/ into .claude/skills/ at the repository root to share it with the project. For personal use across projects, copy it into ~/.claude/skills/. Keep SKILL.md directly inside release-notes/. Claude Code skill locations

Open Claude Code from the project and run /skills. Look for release-notes in the scope you chose. Run /reload-skills if the new skill is missing. If two skills share the name, check their sources. Reload skills during a session

Send the slash command and the change notes in one message.

Claude Code
/release-notes Confirmed: The activity log now offers CSV export. Confirmed: Fixed duplicate entries in the activity log after a refresh. Unverified: CSV export may be twice as fast as the previous internal prototype.

To test automatic selection, start a new session and use the chat prompt with the first line replaced by Draft release notes from these change notes. Look for a Skill call naming release-notes. On supported versions, /skill-doctor reports session usage. Claude Code skill usage reports

If the slash command works but automatic selection fails, check the description, /skills visibility, and Skill permissions. The frontmatter field disable-model-invocation: true reserves the skill for direct invocation. Claude Code invocation controls

Configure the Messages API

Upload the skill to your API workspace

Set ANTHROPIC_API_KEY to a key from your API workspace. Run this from the directory containing release-notes/. The Skills API accepts SKILL.md at the upload root or inside the chat ZIP. The generally available API requires no beta header. Claude API upload formats

Terminal · Upload the skill
curl --fail-with-body https://api.anthropic.com/v1/skills \
  -H "Authorization: Bearer ${ANTHROPIC_API_KEY}" \
  -H 'anthropic-version: 2026-10-21' \
  -F 'files[]=@release-notes/SKILL.md;filename=SKILL.md'

Save the response’s id (skill_…) and latest_version_id (skver_…). Use a key from the same workspace when you send the Messages request. Claude Platform workspace sharing

Send a Messages request with the skill

Replace both placeholders with the IDs from the upload. Pin the version to reuse the same instructions in later tests. Use latest to pick up new versions as you develop. Keep the code execution tool in the request. Messages configuration

Terminal · Send the request
curl --fail-with-body https://api.anthropic.com/v1/messages \
  -H "Authorization: Bearer ${ANTHROPIC_API_KEY}" \
  -H 'anthropic-version: 2026-10-21' \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "model": "claude-opus-5-5",
  "max_tokens": 4096,
  "container": {
    "skills": [
      {"type": "custom", "skill_id": "YOUR_SKILL_ID", "version": "YOUR_SKILL_VERSION_ID"}
    ]
  },
  "tools": [
    {"type": "code_execution_20250825", "name": "code_execution"}
  ],
  "messages": [
    {
      "role": "user",
      "content": "Use the release-notes skill to draft release notes from these change notes.\n\n- Confirmed: The activity log now offers CSV export.\n- Confirmed: Fixed duplicate entries in the activity log after a refresh.\n- Unverified: CSV export may be twice as fast as the previous internal prototype."
    }
  ]
}
JSON

Check the response’s content blocks for a successful read of /skills/release-notes/SKILL.md. If you see only generic tool activity or draft text, record activation as unknown. How Claude reads skills

For a baseline, repeat the request without container. Keep the prompt, model, and tool the same.

The API container has no internet access and cannot install packages at runtime. If your skill needs external input, fetch it in your application and pass it in the request. Claude API runtime constraints

Check the draft

  • The response starts with Release notes draft.
  • Added covers CSV export for the activity log. Fixed covers duplicate entries after a refresh.
  • Needs confirmation contains the speed claim. The release notes contain only the confirmed changes.
  • The draft stays in the conversation or API response for review.
