Use skills in Claude

Upload a ZIP in Claude, place the skill folder on disk for Claude Code, or list the uploaded skill in a Messages API request. Then check that Claude can use it to draft release notes.

Choose your Claude surface

These setup instructions reflect Claude’s product documentation as of November 27, 2026. Use the release-notes skill from the first-skill guide for all three recipes.

  • Claude chat. You or your organization makes the skill available in Customize. Claude can select it when your request matches its description. Claude Help Center on using skills.
  • Claude Code. For a local installation, you put the skill folder in a project or personal directory. You can invoke it yourself or let Claude select it. Claude Code skills documentation.
  • Messages API. Your application uploads the skill to an API workspace and lists it in the request. Claude can select it from the skills the application supplies. Claude Platform guide to skills in the API.

Upload the skill to Claude

Package the enclosing release-notes folder. Opening the archive should show this structure, with SKILL.md one level below the archive root and name: release-notes in its frontmatter. Claude Help Center on packaging custom skills.

release-notes.zip
└── release-notes/
    └── SKILL.md

With zip installed, run zip -r release-notes.zip release-notes/ from the directory containing the skill folder.

  1. In a personal account, go to Settings → Capabilities and enable Code execution and file creation, labeled Create and edit files in the updated layout. In a managed organization, the owner can check Cloud code execution and file creation, Skills, and User-created skills under Organization settings → Plugins & skills → Policy.
  2. Open Customize → Skills. Select +, then Create skill, then Upload a skill. Choose release-notes.zip.
  3. Find release-notes in the skills list and check that it is enabled. If your owner already provisioned the skill, check your organization’s skills before uploading another copy.

If the skills section is missing or grayed out, start with the code execution setting. If the list is visible and the upload action is absent, check your organization’s creation policy and your role. Claude Help Center on enabling, uploading, and troubleshooting skills.

Start a fresh chat and send the verification prompt below. To check automatic selection, start another fresh chat and replace the first line with Draft release notes from these change notes.

Use the release-notes skill to draft release notes from these change notes.

- Confirmed: The activity log now offers CSV export.
- Confirmed: Fixed duplicate entries in the activity log after a refresh.
- Unverified: CSV export may be twice as fast as the previous internal prototype.

An enabled toggle confirms availability. Check the turn’s activity details if Claude shows them. A skill-use entry naming release-notes or a visible read of that skill’s SKILL.md is evidence that it loaded. If the turn exposes no activation evidence, record activation as unknown and score the draft against the checks below. To compare the drafts, repeat the task in a fresh chat with the skill toggled off.

Install the folder in Claude Code

For a skill shared with a repository, copy the folder to .claude/skills/release-notes/ at the repository root. For a skill you want across projects on this machine, use ~/.claude/skills/release-notes/. Keep SKILL.md directly inside the release-notes directory. Claude Code skill locations.

Open Claude Code from the project. Run /skills and look for release-notes in the scope you chose. If you copied the folder during the session and it is missing, run /reload-skills and check again. Claude Code can also show skills from your signed-in Claude account, so check the source when the same name appears. Claude Code documentation on discovery, synced skills, and reload.

Invoke the local skill explicitly by putting its slash command and your source notes in the same message.

/release-notes Confirmed: The activity log now offers CSV export. Confirmed: Fixed duplicate entries in the activity log after a refresh. Unverified: CSV export may be twice as fast as the previous internal prototype.

Successful slash-command invocation checks that the command resolves. To test automatic selection, start a new session and use the chat prompt with the first line replaced by Draft release notes from these change notes. Look for a call to the Skill tool naming release-notes in the session activity, then score the draft. On supported versions, /skill-doctor reports usage for skills in your session. Claude Code skill usage reports

If the slash command works and the plain request misses, check the skill description, the visibility setting in /skills, and any restrictions on the Skill tool. The Claude Code frontmatter field disable-model-invocation: true reserves the skill for direct invocation. Claude Code invocation controls · Claude Code skill permissions

Configure the Messages API

Upload the skill to your API workspace

Make an API key for the workspace available as ANTHROPIC_API_KEY. Run this from the directory containing release-notes/. The one-file upload places SKILL.md at the upload root. You can also upload the chat ZIP with its enclosing folder. The Skills API is generally available and requires no beta header. Claude Platform upload formats · Create Skill API reference

curl --fail-with-body https://api.anthropic.com/v1/skills \
  -H "Authorization: Bearer ${ANTHROPIC_API_KEY}" \
  -H 'anthropic-version: 2026-10-21' \
  -F 'files[]=@release-notes/SKILL.md;filename=SKILL.md'

Save the response’s id (skill_…) and latest_version_id (skver_…). Use a key from the same workspace when you send the Messages request. Claude Platform workspace sharing

Send a Messages request with the skill

Replace both placeholders below with the IDs from the upload. Pinning the version makes later tests use the same skill instructions. Use latest to pick up new versions as you develop. Include the code execution tool and use a model that supports it. Claude Platform Messages configuration · Claude Platform skill versioning

curl --fail-with-body https://api.anthropic.com/v1/messages \
  -H "Authorization: Bearer ${ANTHROPIC_API_KEY}" \
  -H 'anthropic-version: 2026-10-21' \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "model": "claude-opus-5-5",
  "max_tokens": 4096,
  "container": {
    "skills": [
      {"type": "custom", "skill_id": "YOUR_SKILL_ID", "version": "YOUR_SKILL_VERSION_ID"}
    ]
  },
  "tools": [
    {"type": "code_execution_20250825", "name": "code_execution"}
  ],
  "messages": [
    {
      "role": "user",
      "content": "Use the release-notes skill to draft release notes from these change notes.\n\n- Confirmed: The activity log now offers CSV export.\n- Confirmed: Fixed duplicate entries in the activity log after a refresh.\n- Unverified: CSV export may be twice as fast as the previous internal prototype."
    }
  ]
}
JSON

A successful response confirms that the API accepted the request. Claude decides whether to read the skill. Inspect the response’s content blocks for code execution activity that shows a successful read of /skills/release-notes/SKILL.md. If the response shows only generic code execution or draft text, leave activation unverified. For a baseline, send the same prompt in a fresh request with the container field removed, keeping the model and tool the same. How Claude reads skills · Evaluate and improve a skill

The Messages API skill runs in Anthropic’s code execution container. The container has no internet access or runtime package installation, and any script dependencies must be available in that environment. If release notes need input from an external service, have the application fetch the permitted data and pass it in the request. Use the Claude Code recipe above for discovery from local project files. Claude Platform runtime constraints.

When adding scripts or moving this skill between hosts, check the permissions and dependencies against the destination. Review a skill before you run it · Port and troubleshoot a skill.

Check the draft

  • Added covers CSV export for the activity log. Fixed covers duplicate entries after a refresh.
  • Needs confirmation contains the speed claim. The release notes contain only the confirmed changes.
  • The draft stays in the conversation or API response for review.
