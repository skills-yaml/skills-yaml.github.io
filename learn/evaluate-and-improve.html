Evaluate and improve a skill

Test when your release-notes skill loads, check the drafts it produces, and compare a revision with the current version.

Define what a good run looks like

Start with the release-notes skill you wrote. Check that the intended version appears in your agent’s skill list or configuration. That shows discovery. Then check whether each request actually loads the skill and whether the reply meets the requirements. A good draft can come from the model alone, so score activation and output separately.

Describe when the skill should activate

Say what the skill does and when to use it. “Helps with releases” also fits deployment and publishing, so describe the actual request. To test a rewrite, change only description in SKILL.md. ChatGPT and Codex use that field to match requests to skills. OpenAI’s skill invocation guide

SKILL.md
description: >-
  Draft user-facing release notes, a changelog entry, or a what's-new summary
  from change notes. Use for requests to draft, including when the user
  still needs to supply the notes.

Build an activation test set

Replace [notes] with the three lines below. Send each prompt in a fresh session without explicitly selecting the skill. Add real examples where you have them, including requests that use release vocabulary for other work. OpenAI’s guide to testing skills

Confirmed feature: Added CSV export to the activity log.
Confirmed fix: Corrected the time zone shown on scheduled reports.
Unverified claim: CSV export runs twice as fast.
Release-notes test cases
Case Prompt Expected activation Output checks
Direct request Draft release notes from these changes for customer review. [notes] Yes Puts the feature under Added and the fix under Fixed. Flags the speed claim under Needs confirmation.
Paraphrase Turn this list into a short “what changed” update I can send to users after review. [notes] Yes Includes CSV export and the time-zone fix. Keeps the speed claim in Needs confirmation.
Missing input Write a customer-facing changelog entry for our next release. Yes Asks for change notes and waits.
Unsupported claim Draft customer release notes from “Confirmed feature: Added CSV export.” Include that exports run twice as fast, which we haven't measured yet. Yes Includes CSV export in the draft. Keeps the speed claim in Needs confirmation.
Deployment planning Give me a pre-deployment checklist for a release that adds CSV export. No Returns checklist items for deployment preparation.
Internal review Identify what QA should verify before shipping these changes. Give me a test checklist. [notes] No Addresses the test checklist request.
Publishing request Where do I publish the release notes I already wrote? No Answers the publishing question or asks where the project publishes.

Check the agent’s activity or logs for the skill selection or load. Record unknown if the log cannot establish whether the skill loaded. If an in-scope request misses, check that the skill is available and automatic selection is enabled. Try selecting it explicitly to check the workflow separately.

Score the draft and inspect the run

Give each applicable check a pass or fail. For the direct request, you can check the title Release notes draft and the Added and Fixed headings automatically. Read the draft against the notes and check the following.

  • Both confirmed changes appear in the correct sections, with their scope intact.
  • The speed claim appears only in Needs confirmation, with a note to verify it.
  • The draft uses clear customer-facing language and adds no unsupported dates, versions or benefits.

Check the activity log for attempts to send or publish the draft. If the log gives you only part of the activity, record that check as unknown. If a model grades the text, first compare its scores with drafts a person has graded. OpenAI’s guidance on grading

Compare runs under recorded settings

  1. Set aside a few realistic prompts before you edit the skill. Include a drafting request and a related request the skill should leave alone. Save these for the final comparison.
  2. Run the same prompts against the current and revised skill, with one version installed at a time. Run them with release-notes disabled for a draft-quality baseline. Keep the model, project and other enabled skills the same. Anthropic’s skill testing guide
  3. Start a fresh session for each attempt. Begin with three attempts per prompt and version to see where results vary. Keep the agent and model versions, skill settings, prompt, notes, reply and activity evidence for each run. Anthropic’s guide to agent evaluations
  4. Compare misses, unwanted activations and unknowns for the two enabled versions. Compare draft scores across all three conditions. If another skill seems to interfere, check which skills loaded and rerun that case with release-notes alone.

Revise the smallest part and rerun before release

Fix installation or configuration if the skill is missing from the agent. Revise the description if automatic selection repeatedly misses a drafting request. Revise the body if the skill loads and the draft gets the facts wrong.

Rerun the suite with the held-out prompts. For this skill, require every attempt to ask for missing notes and keep unsupported claims out of the customer draft when those checks apply. Check that the change fixed the problem it targeted and review any new failures. Turn each regression into a saved case with its prompt, expected result, observed result and settings.

If you support several agents, repeat the tests in each one. Once the revision passes, follow the registry guide to update the package.
