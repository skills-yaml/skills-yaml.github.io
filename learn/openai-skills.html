Use skills in Codex, ChatGPT and the OpenAI API

Put a skill in your Codex project, install it through your ChatGPT workspace, or connect it to the runtime your API application uses.

Install a project skill in Codex

Start with the release-notes skill. Copy its folder into .agents/skills/ at the root of your Git repository.

Project skill path
.agents/skills/release-notes/SKILL.md

Open Codex CLI or the IDE extension in the repository. Run /skills or type $ to select release-notes. Codex looks for .agents/skills/ from the working directory up to the Git root.

Use ~/.agents/skills/ for personal skills across repositories. If the skill is missing, check its path and restart Codex. If two skills have the same name, check their paths to find the intended copy. Codex skill locations

Verify the draft

Codex prompt
$release-notes Draft release notes from these change notes.

- Confirmed: The activity log now offers CSV export.
- Confirmed: Fixed duplicate entries in the activity log after a refresh.
- Unverified: CSV export may be twice as fast as the previous internal prototype.

Expect a Release notes draft in the conversation with CSV export under Added and the duplicate-entry fix under Fixed. Put the speed claim only under Needs confirmation. Example draft

Install a shared or uploaded skill in ChatGPT

Workspace-managed skills are available to eligible Business, Enterprise, Healthcare, and Edu users. If you can’t see the Skills tab or upload option, check your workspace permissions. ChatGPT workspace settings

  1. Open Plugins in the sidebar, then select Skills in the Plugin Directory.
  2. Select Add, then Upload from your computer to upload your copy. For a shared copy, find it under Shared with me or Shared by your workspace, then choose Install from its menu.
  3. Check Installed for release-notes. In a new chat, type @, select the skill, then paste the drafting request and sample notes after the selected mention. Check that the draft sorts the confirmed changes and keeps the speed claim under Needs confirmation.

ChatGPT scans uploads. Review a skill yourself before installing or sharing it. Review a skill before you run it

In the desktop app, open Skills in the sidebar to see standalone skills across projects. Plugins can also distribute skills to Chat and Work on the web, desktop, and mobile. Standalone skills and plugins

Provision a skill in the OpenAI API

Attach skills to the shell environment in the Responses API, or register the directory containing them in an Agents API sandbox. OpenAI API skills

Responses API with hosted shell

  1. From the directory containing release-notes/, run the commands below to upload a ZIP with release-notes/ as its only top-level folder.
  2. Record the skill ID and version. Check GET /v1/skills/{skill_id}/versions/{version} before attaching the new version. If retrieval briefly returns 404 after upload, retry with a short backoff and a timeout.
  3. On the Responses API request, add the shell tool entry below to tools, using your uploaded ID and version. In input, ask the model to use the release-notes skill to draft from the sample change notes. Hosted shell request examples
Upload the skill package
zip -r release-notes.zip release-notes/
curl --fail-with-body https://api.openai.com/v1/skills \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F 'files=@release-notes.zip;type=application/zip'
Responses API shell tool
{
  "type": "shell",
  "environment": {
    "type": "container_auto",
    "skills": [
      { "type": "skill_reference", "skill_id": "<skill_id>", "version": "<version>" }
    ]
  }
}

You can also supply an inline skill entry with the skill name, description, and base64-encoded ZIP in the hosted environment’s skills array.

Responses API with local shell

Copy release-notes/ into your shell executor’s runtime. Set the shell environment type to local and add the skill’s name, description, and runtime folder path to environment.skills.

Send the same prompt as in hosted mode. Run each shell_call in your executor and return a shell_call_output with the original call ID. Local shell setup and executor example

Agents API sandbox

For an existing self-hosted sandbox, copy the skill into /workspace/skills/release-notes/ inside that sandbox. When creating the session, register its existing parent directory in environment.capability_directories, as shown below. Use an absolute path inside the sandbox. Agents API capability directories

Agents API session configuration
{
  "environment": {
    "type": "self_hosted",
    "workspace_directory": "/workspace",
    "capability_directories": ["/workspace/skills"]
  }
}

Send the sample notes in the session with the request Use the release-notes skill to draft release notes. For any API setup, check the final text against the expected draft. If tool activity is visible, check that the agent read the intended SKILL.md. If the agent cannot read the file, check the attached version or verify the path from inside the execution environment.

Configure optional OpenAI metadata

Add agents/openai.yaml inside the skill folder if you need OpenAI-specific settings. The file can customize the ChatGPT desktop display, declare MCP tool dependencies, or set invocation policy. Set policy.allow_implicit_invocation to false to disable automatic selection in Codex. You can still invoke $release-notes explicitly. OpenAI’s optional metadata reference

Keep the reusable instructions in SKILL.md so you can use the same workflow in another host. Port and troubleshoot a skill
