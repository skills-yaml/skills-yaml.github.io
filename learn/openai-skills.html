Use skills in Codex, ChatGPT and the OpenAI API

Put a skill in your Codex project, install it through your ChatGPT workspace, or connect it to the runtime your API application uses.

Install a project skill in Codex

Product details checked November 27, 2026. This walkthrough uses the complete release-notes skill from the first-skill guide.

Copy the entire release-notes/ folder into .agents/skills/ at your repository root. The skill file should land at this path.

.agents/skills/release-notes/SKILL.md

Open Codex CLI or the IDE extension in that repository. Codex searches .agents/skills/ from its working directory up to the Git root. Run /skills and look for release-notes, or type $release-notes to select it in your prompt. OpenAI’s local skill discovery guide · OpenAI’s skill invocation guide

For personal skills across repositories, use ~/.agents/skills/. If you see two entries with the same name, check the installation paths for the intended copy. If a skill is missing, check the working directory and skill path, then restart Codex. A large catalog can also trigger a warning that some entries were omitted from the model’s initial list. Codex can still read the full instructions when it selects the skill. OpenAI’s discovery and context budget guidance

Verify the draft

$release-notes Draft release notes from these change notes.

- Confirmed: The activity log now offers CSV export.
- Confirmed: Fixed duplicate entries in the activity log after a refresh.
- Unverified: CSV export may be twice as fast as the previous internal prototype.

Expect a Release notes draft in the conversation with CSV export under Added and the duplicate-entry fix under Fixed. The speed claim belongs under Needs confirmation for the reviewer. The run should end with the draft in the conversation. Example draft

Install a shared or uploaded skill in ChatGPT

Workspace-managed skills are available to eligible Business, Enterprise, Healthcare, and Edu users. Controls and availability depend on your workspace settings and the ChatGPT surface you use. If you cannot see the Skills tab or upload option, check your active workspace and its skill permissions. OpenAI’s ChatGPT skills help

  1. Open Plugins in the sidebar, then select Skills in the Plugin Directory.
  2. For a teammate’s skill, find it under Shared with me or your workspace’s shared skills, then open its menu and select Install. To upload your own copy, select Add, then Upload from your computer, and choose the skill file using the upload dialog.
  3. Check Installed for release-notes. In a new chat, type @, select the skill, then paste the drafting request and sample notes after the selected mention. Check that the draft sorts the confirmed changes and keeps the speed claim under Needs confirmation.

ChatGPT scans uploaded skills before making them available. An upload can require review or be blocked. Review the instructions and files yourself before using or sharing an uploaded skill. OpenAI’s upload and workspace controls · OpenAI’s skill invocation guide · Review a skill before you run it

To see standalone skills across your projects in the ChatGPT desktop app, open Skills in the sidebar. Standalone skills are also available in Codex CLI and the IDE extension. An installable plugin can distribute skills and connectors, including to Chat and Work on the web, desktop, and mobile. Installation and syncing depend on the product and surface. OpenAI’s standalone and plugin skill guidance · ChatGPT skills help

Provision a skill in the OpenAI API

Your application must provision both the skill and the runtime that can read it. After you provision the skill, ask the model to use release-notes. The model can then select it and read its instructions. OpenAI API skill prompting behavior

Responses API with hosted shell

  1. From the directory containing release-notes/, run the commands below to upload a ZIP with release-notes/ as its only top-level folder. Upload a skill bundle
  2. Record the skill ID and version. Check GET /v1/skills/{skill_id}/versions/{version} before attaching the new version. If retrieval briefly returns 404 after upload, retry with a short backoff and a timeout. Check version readiness
  3. On the Responses API request, add the shell tool entry below to tools, using your uploaded ID and version. In input, ask the model to use the release-notes skill to draft from the sample change notes. Hosted shell request examples
zip -r release-notes.zip release-notes/
curl --fail-with-body https://api.openai.com/v1/skills \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F 'files=@release-notes.zip;type=application/zip'
{
  "type": "shell",
  "environment": {
    "type": "container_auto",
    "skills": [
      { "type": "skill_reference", "skill_id": "<skill_id>", "version": "<version>" }
    ]
  }
}

You can also supply an inline skill entry with the skill name, description, and base64-encoded ZIP in the hosted environment’s skills array. Inline bundle format

Responses API with local shell

Copy release-notes/ into the runtime that executes shell calls. Set the shell environment’s type to local and add the skill’s name, description, and folder path as seen from inside that runtime to environment.skills. Send the same prompt as in hosted mode. Your application runs each shell_call in its execution environment and submits a shell_call_output with the original call ID. Continue until the API returns the draft. Local shell setup and executor example

Agents API sandbox

For an existing self-hosted sandbox, copy the skill into /workspace/skills/release-notes/ inside that sandbox. When creating the session, register its existing parent directory in environment.capability_directories, as shown below. These paths must be absolute and point to directories inside the sandbox. Once the sandbox is available, the agent discovers the skill’s name and description and can read the full instructions when it selects the skill. Agents API capability directories

{
  "environment": {
    "type": "self_hosted",
    "workspace_directory": "/workspace",
    "capability_directories": ["/workspace/skills"]
  }
}

Send the sample notes in the session with the request Use the release-notes skill to draft release notes. For any API setup, check the final text against the expected draft. When tool activity is visible, check for a read of the intended SKILL.md as evidence that the agent loaded it. If the agent cannot read the file, check the attached version or verify the path from inside the execution environment. How Responses API skill discovery works

Configure optional OpenAI metadata

Add agents/openai.yaml inside the skill folder if you need OpenAI-specific settings. The file can customize the ChatGPT desktop display, declare MCP tool dependencies, or set invocation policy. Setting policy.allow_implicit_invocation to false makes Codex require explicit selection, such as $release-notes. OpenAI’s optional metadata reference

Keep the reusable instructions in SKILL.md so you can use the same workflow in another host. Port and troubleshoot a skill
