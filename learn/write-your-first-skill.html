Agent Skills learning center

Write your first SKILL.md

Create a skill that turns supplied change notes into a reviewable draft. Copy the entire file, check that it follows the Agent Skills format, and try it with sample notes in your agent.

Create release-notes/SKILL.md

Create a folder named release-notes and save a plain-text file named SKILL.md inside it.

release-notes/
└── SKILL.md

Copy the complete skill

Copy the whole block into SKILL.md. Start the file with the first --- line. The second --- line ends the YAML frontmatter, and the Markdown instructions begin below it.

release-notes/SKILL.md
---
name: release-notes
description: >
  Draft user-facing release notes from supplied change notes.
  Use when the user asks for a release-note draft or a draft changelog entry.
---

# Draft release notes

1. If the user supplies no change notes, ask them to paste the notes and wait before drafting.
2. Use only the supplied notes as evidence. Include user-visible changes that the notes present as confirmed. Preserve any stated limits on availability or scope.
3. Put tentative, contradictory, or unsupported claims under a separate "Needs confirmation" heading for the reviewer. Identify what must be confirmed and keep those claims out of the release notes. Avoid inferring dates, versions, or benefits.
4. Start with "Release notes draft". Group bullets under "Added", "Changed", or "Fixed" as appropriate and omit empty groups. If no user-facing change is confirmed, say so.
5. Return the draft and any confirmation items in the conversation. Never publish or send the draft elsewhere.

The agent first sees the name and description. Phrases such as “release-note draft” and “draft changelog entry” tell it when the skill applies. The Markdown body tells it what to do with confirmed changes, unverified claims and missing notes. OpenAI guidance on writing skills

Read the frontmatter

Include name and description in the YAML at the top of the file.

  • Match name to the folder name. Use 1–64 characters and stick to lowercase letters a–z, digits and single hyphens between words.
  • Keep description to 1–1,024 characters. Say what the skill does and when to use it. The YAML > folds the two indented lines into a single description.

Claude also reserves anthropic and claude in skill names and rejects XML tags in descriptions. Claude's skill file requirements

Start with the two required fields. If you need extra information, put author and version under metadata as strings. Describe runtime requirements in compatibility using up to 500 characters. Check your agent's documentation before adding tool configuration.

Validate and test a draft

Check the file format

From the directory that contains release-notes/, check the frontmatter with Anthropic's quick_validate.py. These macOS and Linux commands use Git and Python 3 and install PyYAML in a virtual environment. Anthropic's validator

Terminal
git clone --depth 1 https://github.com/anthropics/skills.git anthropic-skills
python3 -m venv .skill-validation
.skill-validation/bin/python -m pip install PyYAML
.skill-validation/bin/python anthropic-skills/skills/skill-creator/scripts/quick_validate.py ./release-notes

Expect Skill is valid! Check that name matches the folder yourself. Then use the prompts below to test activation and the draft.

Try a draft in your agent

Install the skill and select it explicitly for the first test. Follow the setup guide for your agent. Claude · Google developer tools · Codex, ChatGPT, and the OpenAI API

Paste this prompt with its sample change notes.

Use the release-notes skill to draft release notes from these change notes.

- Confirmed: The activity log now offers CSV export.
- Confirmed: Fixed duplicate entries in the activity log after a refresh.
- Unverified: CSV export may be twice as fast as the previous internal prototype.

Expect a draft similar to this. Check that both confirmed changes appear under the right headings and the speed claim appears only as a confirmation item.

# Release notes draft

## Added
- Export the activity log as a CSV file.

## Fixed
- Fixed duplicate entries in the activity log after a refresh.

## Needs confirmation
- Verify the claim that CSV export is twice as fast as the previous internal prototype.

In a fresh conversation, select the skill again and ask it to draft release notes without supplying any notes. It should ask you to paste them and wait. For both tests, check that the agent returns its work in the conversation and makes no attempt to publish or send it.

Check when the skill loads

If your agent supports automatic activation, try each prompt in a fresh conversation. Leave the skill unselected and check the agent’s skill indicator or execution trace.

  • “Turn these confirmed changes and open questions into a customer-facing changelog entry.” Include the sample notes. Expect the agent to load release-notes.
  • “Explain how CSV export works in an activity log.” Expect the agent to answer without loading release-notes. It shares the topic of the sample but asks for an explanation.

Repeat automatic activation checks when results vary. If the agent loads the skill for unrelated work, narrow the description. If it loads the skill and produces a poor draft, tighten the instructions and repeat the explicit test. Evaluate and improve a skill · OpenAI’s guide to skill evals

Add a reference or template

Save a house style guide at release-notes/references/style-guide.md. Add a drafting step that tells the agent when to read it. Link directly from SKILL.md using a path relative to the skill folder. Claude's guidance on references

For customer-facing drafts, read [the style guide](references/style-guide.md) before writing.

Put reusable templates such as release-template.md in assets/. Use scripts/ when the agent needs to run a repeatable check, such as validating draft headings. Give the command, working directory, inputs, and expected result. List any runtime or packages it needs and check that the agent can run it. OpenAI guidance on supporting files
