Agent Skills learning center

Write your first SKILL.md

Create a skill that turns supplied change notes into a reviewable draft. Copy the entire file, check that it follows the Agent Skills format, and try it with sample notes in your agent.

Create release-notes/SKILL.md

Create a folder called release-notes and save a plain-text file named SKILL.md inside it. Start with this single file. You can move the whole folder into the location your agent expects when you are ready to try it. Agent Skills directory structure

release-notes/
└── SKILL.md

Copy the complete skill

Copy the whole block into SKILL.md. Start the file with the first --- line. The second --- line ends the YAML frontmatter, and the Markdown instructions begin below it.

release-notes/SKILL.md
---
name: release-notes
description: >
  Draft user-facing release notes from supplied change notes.
  Use when the user asks for a release-note draft or a draft changelog entry.
---

# Draft release notes

1. If the user supplies no change notes, ask them to paste the notes and wait before drafting.
2. Use only the supplied notes as evidence. Include user-visible changes that the notes present as confirmed. Preserve any stated limits on availability or scope.
3. Put tentative, contradictory, or unsupported claims under a separate "Needs confirmation" heading for the reviewer. Identify what must be confirmed and keep those claims out of the release notes. Avoid inferring dates, versions, or benefits.
4. Start with "Release notes draft". Group bullets under "Added", "Changed", or "Fixed" as appropriate and omit empty groups. If no user-facing change is confirmed, say so.
5. Return the draft and any confirmation items in the conversation. Never publish or send the draft elsewhere.

The description gives an agent enough information to decide when to load the skill. Here, “release-note draft” and “draft changelog entry” describe the user's intent. The body covers what to do after activation. It names the evidence to use, the exception for missing notes, and the structure of a finished draft. Keep instructions specific to the workflow so the body stays short as you refine it. Best practices for skill creators · Optimizing skill descriptions

Read the frontmatter

The specification requires name and description. Agent Skills frontmatter specification

  • name must match the parent folder exactly. Use 1–64 characters made up of lowercase letters (a-z), digits (0-9), and hyphens. Hyphens cannot appear at either end or in consecutive pairs.
  • description must be 1–1,024 characters. Describe what the skill does and when to use it. The YAML > folds the indented lines in the example into a single description. Keep both lines indented with spaces.

Use the optional fields when they serve the skill. Agent Skills optional fields

  • license identifies the license by name or points to a bundled license file.
  • compatibility documents specific environment requirements, such as system packages. Use 1–500 characters if supplied.
  • metadata holds additional properties as string keys and string values. For example, put version: "1.0" under metadata to keep the version a string.
  • allowed-tools is experimental. It lists preapproved tools as a space-separated string. Whether a host honors it depends on its implementation.

The Skills Directory guide lists version, author, tags, and requires as optional top-level fields. The Agent Skills reference validator rejects these extra top-level fields. Put author and version under metadata as strings, and describe runtime requirements in compatibility. Skills Directory optional fields · Agent Skills frontmatter specification

Validate and test a draft

Check the file format

With Git and Python 3.11 or later available, run these commands from the directory that contains release-notes/. They install the official reference validator in a virtual environment and pass the skill folder to it. The commands below use a macOS or Linux shell. The reference library also provides Windows installation steps. Reference library installation · Agent Skills validation

git clone https://github.com/agentskills/agentskills.git
python3 -m venv .skills-ref-venv
.skills-ref-venv/bin/python -m pip install ./agentskills/skills-ref
.skills-ref-venv/bin/skills-ref validate ./release-notes

Look for Valid skill: release-notes. Use the validator's errors to fix frontmatter or folder naming, then run it again. The following prompts check how the agent uses the instructions.

Try a draft in your agent

Once the validator accepts the frontmatter and folder name, install the skill in your host and explicitly select it for the first test. Follow the setup guide for your host. Claude · Google developer tools · Codex, ChatGPT, and the OpenAI API

Paste this prompt with its sample change notes.

Use the release-notes skill to draft release notes from these change notes.

- Confirmed: The activity log now offers CSV export.
- Confirmed: Fixed duplicate entries in the activity log after a refresh.
- Unverified: CSV export may be twice as fast as the previous internal prototype.

Expect a draft similar to this. Check that both confirmed changes appear under the right headings and the speed claim appears only as a confirmation item.

# Release notes draft

## Added
- Export the activity log as a CSV file.

## Fixed
- Fixed duplicate entries in the activity log after a refresh.

## Needs confirmation
- Verify the claim that CSV export is twice as fast as the previous internal prototype.

In a fresh conversation, select the skill again and ask it to draft release notes without supplying any notes. It should ask you to paste them and wait. For both tests, check that the agent returns its work in the conversation and makes no attempt to publish or send it.

Check when the skill loads

If your agent supports automatic activation, run each prompt in a fresh conversation without explicitly selecting the skill. Check the agent's skill indicator or execution trace, if available. Testing whether a description triggers

  • “Turn these confirmed changes and open questions into a customer-facing changelog entry.” Include the sample notes. Expect the agent to load release-notes.
  • “Explain how CSV export works in an activity log.” Expect the agent to answer without loading release-notes. It shares the topic of the sample but asks for an explanation.

Repeat automatic activation checks when results vary. If the agent loads the skill for unrelated work, narrow the description. If it loads the skill and produces a poor draft, tighten the instructions and repeat the explicit test. Evaluate and improve a skill

Add a reference or template

When you have a house style to apply, save it in release-notes/references/style-guide.md. In SKILL.md, add a step that tells the agent when to read the guide. Link straight from SKILL.md to the file using a path relative to release-notes/. Agent Skills file references

For customer-facing drafts, read [the style guide](references/style-guide.md) before writing.

Use assets/ for static resources. For example, save a required output template as assets/release-template.md and point to it in the drafting step. Keep detailed guidance in references/ and tell the agent which task calls for each file. Agent Skills optional directories

Use scripts/ for a repeatable check the agent can run, such as a script that validates draft headings. If you add one, document the command, where to run it, its input and output, and any runtime or package requirements. Use compatibility for environment prerequisites such as a minimum Python version. Confirm that the host allows script execution and tell the agent how to proceed if the script is unavailable. Using scripts in skills
