One manifest.Every agent.

You write the skills your project needs into skills.yaml and commit it. skm resolves them from a registry and links them into Claude, Codex, Cursor, Copilot, Grok and Hermes, so every agent working in the repo reads the same instructions.

Skills are versioned directories in Git. Pin one, follow latest, or track the maintainer's default.

Install on macOS or Linux

curl -fsSL https://raw.githubusercontent.com/skills-yaml/skm/main/scripts/install.sh | sh

Windows PowerShell, Cargo and the development channel are covered in the install guide.

What lands on disk

Nothing is copied into your tree. skm creates symlinks, so a skill update is a re-link, and reviewers see one manifest change instead of hundreds of vendored files.

In a project

Run skm install in a repo. Links go next to the agent configuration already in the project.

my-project/
├── skills.yaml
├── skills.lock.yaml
├── .claude/skills/  -> linked skills
├── .codex/skills/   -> linked skills
├── .cursor/skills/  -> linked skills
├── .github/skills/  -> linked skills
├── .grok/skills/    -> linked skills
└── .hermes/skills/  -> linked skills

For your user account

Add --global to install, list or check to work on the agent directories in your home folder instead.

The manifest

Everything skm does starts here. Fields you leave out keep working defaults, and toolkit projects add a few more.

name: my-project
version: 0.1.0

registries:
  default: git@github.com:skills-yaml/registry.git

agents:
  - claude
  - codex
  - cursor
  - copilot

skills:
  - name: software-development/spec
    version: 1.0.0        # pinned
    source: default

  - name: system/gcp-debug
    version: latest       # follows the newest release
    source: default

  - name: local/my-skill  # no registry needed
    version: latest
    path: ./skills/local/my-skill
registries
Git remotes or local paths to fetch skills from. Name them, then refer to a name in source. A project inherits your global registries too.
agents
Which agents get links. Add one later and re-run skm install to fill its directory.
version
A pinned release such as 1.0.0, or the latest and default aliases the skill's maintainer moves. Omit it and you get latest.
path
Point at a directory in the repo instead of a registry. Useful for a skill that is not ready to publish. Every source needs a SKILL.md.
skills.lock.yaml
Written by skm install, committed by you. It records the resolved versions, integrity hashes and every path skm manages, so a second install is byte-for-byte identical.

Commands

One binary, no daemon, no project scaffolding beyond the manifest.

Add --global to install, list and check to target your home directory. Add --json where a script needs to read the result.
CommandWhat it does
Set up
skm initBuilds skills.yaml in a terminal wizard, with a live preview and a searchable list of the skills in your registries. --non-interactive writes a default manifest for scripts.
skm search <query>Searches your registries by skill name and prints the command that adds each result. --add takes an unambiguous match straight into the manifest.
skm add <skill>Adds one skill to the manifest and links it.
Keep it correct
skm installResolves every skill, checks each target before writing, links them, then writes the lockfile. --dry-run shows every write first.
skm listReports link status, including sources that went missing and links that point somewhere wrong.
skm checkVerifies sources, SKILL.md files and symlink targets. Run it in CI.
skm updateUpdates the skm binary itself from the production or development channel.
Move between versions
skm versions <skill>Lists the releases a registry offers for one skill.
skm use <skill>@<version>Switches a skill to a specific version and re-links it.
skm update-skill <skill>Moves a skill to its newest release and re-links it.
Write a skill
skm dev link <path>Links a skill you are editing straight from disk, so you can try it in your agents before publishing.
skm dev list, show, modeShows what is linked in development, and turns development mode on or off.
skm dev unlink <skill>Removes a development link.
Workspace toolkits
skm workspace auditReports how your repo compares with a trusted workspace-docs package.
skm workspace adoptAlso upgrade and repair. Each plans first and applies only with --apply, and can resume where it stopped.

Guardrails

Agent skills end up as instructions your team executes. skm treats writing them to disk as a transaction.

  • It refuses collisions

    Before writing anything, skm checks every target. A file it does not already manage stops the install instead of being overwritten.

  • It rolls back

    A local journal backs up managed paths during apply. A failure part-way through restores what was there, and the lockfile is written last.

  • It verifies sources

    Git sources need a full commit revision and an expected SHA-256. Skill and registry names are validated before any filesystem call: no absolute paths, no .., no unsupported agents.
